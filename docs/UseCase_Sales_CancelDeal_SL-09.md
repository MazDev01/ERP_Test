# เอกสารรายละเอียดยูสเคส (Use Case Description)
## ระบบ ERP MAZ — โมดูลงานขาย (Sales Module) · ยูสเคส SL-09 ยกเลิกดีลหลังปิดการขาย
บริษัท ไอเมซเมกเกอร์ จำกัด | ฉบับย้อนคำตัดสินเรื่องใบลดหนี้ 24 ก.ย. 2569 — กลับไปใช้กระบวนการเดิมของระบบ

## ขอบเขตของเอกสาร

- เอกสารฉบับนี้เป็นยูสเคส **SL-09 เพียงรายการเดียว** เขียนด้วยรูปแบบเดียวกับ `UseCase_PM.docx` และ `UseCase_GM.docx`
- **SL-09 กลับไปเป็นรูปเดิมก่อนมีใบลดหนี้** ขั้นการคืนเงินและขั้นอนุมัติของผู้บริหารที่เพิ่มไว้เมื่อเช้าวันที่ 24 ก.ย. 2569 **ถูกถอดออกทั้งหมด** · ยูสเคส AC-01 ถึง AC-03 (ใบลดหนี้ ใบเพิ่มหนี้ การคืนเงิน) ยกเลิกทั้งชุด ดู `docs/UseCase_Accounting_CreditNote.md` ซึ่งเก็บไว้เป็นบันทึกคำตัดสินที่ถูกยกเลิก
- ⚠️ **ยังไม่มีเอกสารยูสเคสของโมดูลงานขายฉบับเต็มในโปรเจคนี้** จึงเขียน SL-09 แยกเป็นไฟล์เดี่ยวไว้ก่อน เมื่อรวมกลับเข้าเอกสารโมดูลงานขายให้ยืนยันเลขหัวข้อ (ใช้ **3.2.9** ไปก่อน) และตรวจว่าเลข SL-09 ยังว่างอยู่จริง · การวางบิลและออกใบเสร็จถูกอ้างในชื่อ SL-05 ตามเอกสารเดิม
- **สิ่งที่เปลี่ยนจากฉบับเมื่อเช้า มีสามข้อ** — (1) ถอดขั้นการคืนเงินและขั้นอนุมัติของผู้บริหารออก (2) เปลี่ยนถ้อยคำ "ฝ่ายบัญชีดำเนินการนอกระบบ" เป็น **"บริษัทไม่คืนเงินทุกกรณี"** ตามที่เจ้าของระบบสั่ง (3) เพิ่มช่องบันทึกเพิ่มเติมของการยกเลิกที่ **ไม่บังคับกรอก**

## 3.2.9 Use Case: ยกเลิกดีลหลังปิดการขาย (Cancel Deal)

| | |
| --- | --- |
| **ชื่อยูสเคส** | ยกเลิกดีลหลังปิดการขาย · **รหัส** SL-09 · ระดับความสำคัญ: มาก |
| **ผู้กระทำหลัก** | - พนักงานขาย (กรณีดีลยังไม่ได้รับเงินจากลูกค้า)<br>- พนักงานบัญชี (กรณีดีลรับเงินไปแล้ว) · **ประเภทยูสเคส** เชิงละเอียด |
| **ผู้มีส่วนเกี่ยวข้องและการใช้ประโยชน์** | พนักงานขาย : ปิดเรื่องดีลที่ลูกค้ายุติ ไม่ต้องค้างอยู่ในรายการติดตาม<br>พนักงานบัญชี : หยุดการวางบิลงวดที่เหลือ และปิดยอดค้างของใบแจ้งหนี้ที่ยังไม่ได้รับชำระ พร้อมบันทึกไว้ว่าตกลงอะไรกับลูกค้า<br>ผู้จัดการโครงการ : รู้ทันทีว่างานหยุด ไม่ทำงานที่ไม่ได้เงินต่อ<br>ผู้บริหาร : เห็นเหตุผลการยกเลิกและผู้ยกเลิกย้อนหลังได้ทุกรายการ |
| **คำอธิบาย** | เมื่อลูกค้ายุติโครงการหลังจากปิดการขายไปแล้ว ผู้มีสิทธิ์ตามกติกาจะยกเลิกดีลพร้อมระบุเหตุผล ระบบบันทึกผู้ยกเลิกและวันเวลาที่ยกเลิก ปิดการวางบิลงวดที่เหลือ ยกเลิกใบแจ้งหนี้ที่ยังไม่ได้รับชำระของดีลนั้นทุกใบ และเปลี่ยนโปรเจคของดีลเป็นยกเลิก · **ใบเสร็จรับเงินที่ออกไปแล้วยังอยู่ครบ ไม่ถูกแก้ และบริษัทไม่คืนเงินทุกกรณี** ฝ่ายบัญชีบันทึกเพิ่มเติมได้ว่าตกลงอะไรกับลูกค้าไว้ |
| **สิ่งกระตุ้น** | ลูกค้าแจ้งยุติโครงการ · พนักงานขายเปิดหน้าดีล หรือพนักงานบัญชีเปิดหน้าวางบิล แล้วกดยกเลิกดีล |
| **ความสัมพันธ์** | ความเกี่ยวเนื่อง : พนักงานขาย พนักงานบัญชี<br>ต่อยอดจาก : ปิดการขาย · การวางบิลและออกใบเสร็จ (SL-05)<br>ส่งผลถึง : รับงานเข้าใหม่ (PM-01) — โปรเจคของดีลเปลี่ยนเป็นยกเลิกและงานหยุด |
| **เงื่อนไขก่อนเริ่ม** | 1. ผู้ใช้เข้าสู่ระบบด้วยบทบาทพนักงานขายหรือพนักงานบัญชี<br>2. ดีลอยู่ในสถานะปิดการขาย และยังไม่เคยถูกยกเลิก<br>3. **สิทธิ์ยกเลิกตัดสินจากการรับเงิน** — ดีลที่ยังไม่มีใบเสร็จรับเงินเลยเป็นของฝ่ายขาย ดีลที่มีใบเสร็จแล้วอย่างน้อยหนึ่งใบเป็นของฝ่ายบัญชี |
| **ขั้นตอนการทำงานปกติ** | 1. ผู้ใช้เปิดดีลที่ต้องการยกเลิกแล้วกดยกเลิกดีล ระบบแสดงกล่องยืนยันพร้อมลูกค้า มูลค่าดีล ยอดที่รับชำระแล้ว และรายการใบแจ้งหนี้ที่จะถูกยกเลิก<br>2. ผู้ใช้กรอก **เหตุผลที่ยกเลิก** ระบบบังคับให้มีเหตุผลทุกครั้ง ยกเลิกโดยไม่มีเหตุผลไม่ได้<br>3. ผู้ใช้กรอก **บันทึกเพิ่มเติม (ไม่บังคับ)** — ที่ว่างให้ฝ่ายบัญชีจดว่าตกลงอะไรกับลูกค้าไว้ เช่นออกเอกสารอะไรในโปรแกรมบัญชีของฝ่ายบัญชีเอง หรือแจ้งลูกค้าไปทางใด ว่างไว้ก็ยกเลิกได้<br>4. ระบบเตือนให้เห็นก่อนกดว่าอะไรจะเกิดขึ้นกับฝ่ายอื่น — ใบแจ้งหนี้ที่ยังไม่ได้รับชำระจะถูกยกเลิกไปด้วย โปรเจคของ PM เปลี่ยนเป็นยกเลิกและงานหยุดทันที · กรณีฝ่ายบัญชีเป็นผู้ยกเลิก ระบบเตือนเพิ่มว่า **ใบเสร็จที่ออกไปแล้วยังอยู่ตามเดิม และระบบไม่คืนเงินให้เอง**<br>5. ผู้ใช้กดยืนยัน ระบบบันทึกการยกเลิกที่ดีลพร้อม **ผู้ยกเลิก วันเวลาที่ยกเลิก เหตุผล และบันทึกเพิ่มเติมถ้ามี**<br>6. ระบบยกเลิกใบแจ้งหนี้ของดีลนั้น **เฉพาะใบที่ยังมียอดค้าง** ตั้งยอดค้างเป็นศูนย์ และบันทึกผู้ยกเลิกกับวันเวลาไว้ที่ใบนั้นทุกใบ · ใบที่รับชำระครบแล้วไม่ถูกแตะ<br>7. ระบบปิดการวางบิลงวดที่เหลือ งวดถัดไปของดีลนี้ออกใบแจ้งหนี้ไม่ได้อีก โดยแผนงวดยังอยู่ครบไม่ถูกลบ<br>8. ระบบเปลี่ยนโปรเจคของดีลเป็นยกเลิก งานของทีมผลิตหยุด<br>9. **ไม่มีขั้นการคืนเงินและไม่มีขั้นอนุมัติ** — เรื่องจบที่ขั้นตอนนี้ ใบเสร็จและเงินที่รับมาแล้วไม่เปลี่ยน **บริษัทไม่คืนเงินทุกกรณี** |
| **ขั้นตอนการทำงานย่อย** | S-1 : กรณีดีลยังไม่ได้รับเงินเลย<br>ผู้ยกเลิกคือฝ่ายขาย ใบแจ้งหนี้ที่ออกไปแล้วแต่ยังไม่ได้รับชำระถูกยกเลิกตาม ถ้ายังไม่เคยออกใบแจ้งหนี้เลยก็ไม่มีเอกสารใดต้องยกเลิก<br><br>S-2 : กรณีดีลรับเงินไปแล้วบางงวด<br>ผู้ยกเลิกคือฝ่ายบัญชี ใบแจ้งหนี้ของงวดที่ยังไม่ได้รับชำระถูกยกเลิก ส่วนงวดที่รับเงินแล้วมีใบเสร็จอยู่ครบและ **เงินไม่ถูกคืน** ยอดรับเงินจริงในรายงานไม่เปลี่ยน<br><br>S-3 : กรณีต้องออกเอกสารกลับรายการให้ลูกค้า<br>ระบบนี้ไม่ออกเอกสารกลับรายการ ฝ่ายบัญชีออกเอกสารในโปรแกรมบัญชีของฝ่ายบัญชีเอง แล้ว **จดเลขที่หรือวิธีที่แจ้งลูกค้าไว้ในช่องบันทึกเพิ่มเติมของขั้นตอนที่ 3** เพื่อให้คนที่มาสอบทานย้อนหลังตามเรื่องได้<br><br>S-4 : กรณีเปิดกล่องยกเลิกแล้วเปลี่ยนใจ<br>กดปิดได้ ไม่มีอะไรถูกบันทึก ไม่มีสถานะค้าง |
| **ขั้นตอนกรณีมีข้อยกเว้น** | E-1 : ไม่กรอกเหตุผล — ระบบไม่ยกเลิกให้ และแจ้งว่า "ใส่เหตุผลก่อนยกเลิก"<br>E-2 : ดีลไม่ได้อยู่ในสถานะปิดการขาย หรือถูกยกเลิกไปแล้ว — ระบบปฏิเสธ ยกเลิกซ้ำไม่ได้<br>E-3 : ผู้ใช้ไม่ใช่ฝ่ายที่มีสิทธิ์ตามกติกาข้อรับเงิน — ระบบปฏิเสธแม้กดจากหน้าของตัวเอง เช่นฝ่ายขายกดยกเลิกดีลที่รับเงินไปแล้ว<br>E-4 : บันทึกเพิ่มเติมว่างเปล่า — **ไม่ใช่ข้อผิดพลาด** ระบบยกเลิกให้ตามปกติ<br>E-5 : ผู้ใช้คาดหวังให้ระบบคืนเงินให้ลูกค้า — ระบบไม่มีความสามารถนี้ และไม่มีเมนูให้ทำ **บริษัทไม่คืนเงินทุกกรณี** |
| **เงื่อนไขเมื่อจบ** | 1. ดีลมีสถานะยกเลิก พร้อมชื่อผู้ยกเลิก วันเวลาที่ยกเลิก และเหตุผล · มีบันทึกเพิ่มเติมด้วยถ้าผู้ใช้กรอกไว้<br>2. ใบแจ้งหนี้ที่ยังมียอดค้างของดีลนั้นมีสถานะยกเลิก ยอดค้างเป็นศูนย์ พร้อมชื่อผู้ยกเลิกและวันเวลาทุกใบ และหลุดจากรายการติดตามหนี้และการแจ้งเตือน<br>3. **ใบเสร็จรับเงินและรายการเงินรับยังอยู่ครบ ไม่ถูกแก้ ไม่ถูกยกเลิก และไม่มีเงินไหลออกจากบริษัท**<br>4. แผนงวดชำระยังอยู่ครบทุกงวด ไม่มีงวดใดถูกลบหรือแก้ยอด แต่ออกใบแจ้งหนี้งวดถัดไปไม่ได้<br>5. โปรเจคของดีลมีสถานะยกเลิก งานของทีมผลิตหยุด<br>6. ยอดวางบิลและยอดค้างชำระบนแดชบอร์ดบัญชีลดลงตามใบที่ถูกยกเลิก ส่วนยอดรับเงินจริงไม่เปลี่ยน<br>7. ไม่มีคำขอใดค้างอยู่บนหน้าอนุมัติของผู้บริหาร ยูสเคสนี้ไม่ผ่านการอนุมัติ |

## ข้อสมมติและข้อจำกัดที่รับไว้แล้ว

**ข้อจำกัด** — เมื่อยกเลิกดีลที่วางบิลไปแล้ว ระบบตัดยอดตามใบแจ้งหนี้ที่ยังไม่ได้รับชำระออกจากยอดวางบิลและยอดค้างชำระ แต่ **ลูกค้าได้รับใบแจ้งหนี้ใบนั้นไปแล้วและบันทึกบัญชีตามเอกสารที่ได้รับ** ไม่มีเอกสารใดจากระบบนี้ไปกลับรายการให้ลูกค้า **ตัวเลขในระบบกับเอกสารที่อยู่ในมือลูกค้าจึงไม่ตรงกันได้** และยอดที่รับเงินมาแล้วก็ไม่ถูกคืนไม่ว่ากรณีใด

**สถานะ** — เจ้าของระบบรับทราบและยอมรับข้อจำกัดนี้ด้วยตนเองเมื่อ 24 ก.ย. 2569 หลังจากฟังคำอธิบายว่าใบลดหนี้มีไว้ทำอะไร ไม่ใช่เรื่องที่มองข้ามไป · เหตุผลคือเอกสารกลับรายการทั้งหมดออกจากโปรแกรมบัญชีของฝ่ายบัญชีเอง ระบบนี้ไม่ใช่ระบบบัญชีของบริษัท · ช่องบันทึกเพิ่มเติมตามขั้นตอนที่ 3 มีไว้เชื่อมสองฝั่งเข้าหากันด้วยข้อความ ไม่ใช่ด้วยตัวเลข

**เงื่อนไขที่จะทำให้ต้องทบทวน** — ถ้าฝ่ายบัญชีหรือผู้สอบบัญชีทักท้วงเรื่องนี้ ให้เปิดเรื่องใบลดหนี้ขึ้นใหม่ · โค้ดของใบลดหนี้ ใบเพิ่มหนี้ และการคืนเงินยังอยู่ครบในโปรเจค (พักไว้ ไม่ได้ลบ ดูหมายเหตุหัวส่วนใน `src/lib/acc-data.ts`) และยูสเคส AC-01 ถึง AC-03 พร้อมคืนตามความหมายเดิมจาก `docs/UseCase_Accounting_CreditNote.md`

## ประเด็นที่ยังต้องยืนยันกับเจ้าของระบบ

การย้อนคำตัดสินครั้งนี้ทิ้งเรื่องที่ยังไม่ได้ตัดสินไว้ ผู้เขียนเอกสารไม่ตั้งคำตอบเอง

| ประเด็น | ข้อเสนอของผู้เขียนเอกสาร |
| --- | --- |
| **รหัสและเลขหัวข้อของยูสเคสนี้** | ยังไม่มีเอกสารยูสเคสโมดูลงานขายฉบับเต็มในโปรเจค · **เสนอ: ใช้ SL-09 และหัวข้อ 3.2.9 ไปก่อน** แล้วยืนยันตอนรวมกลับเข้าเอกสารโมดูลงานขาย ถ้าเลข SL-09 ถูกใช้ไปแล้วให้ย้ายยูสเคสนี้ไปเลขถัดไป ไม่ใช่สลับกับของเดิม |
| **บันทึกเพิ่มเติมแก้ย้อนหลังได้หรือไม่** | ตอนนี้กรอกได้ครั้งเดียวตอนยกเลิก · **เสนอ: ให้ฝ่ายบัญชีแก้ได้ภายหลัง** เพราะข้อตกลงกับลูกค้ามักสรุปหลังกดยกเลิกไปแล้ว แต่ต้องลงประวัติว่าใครแก้เมื่อไร |
| **ฝ่ายขายควรเห็นช่องบันทึกเพิ่มเติมด้วยหรือไม่** | ตอนนี้กล่องยกเลิกใบเดียวกันใช้ทั้งสองฝ่าย ช่องจึงขึ้นให้ฝ่ายขายด้วย แต่ข้อความถูกเก็บไว้ที่ฝั่งบัญชีเท่านั้น · **เสนอ: คงไว้แบบนี้** เพราะฝ่ายขายอาจมีข้อตกลงกับลูกค้าที่ควรบันทึกเหมือนกัน ถ้าเจ้าของระบบเห็นว่าเป็นเรื่องของบัญชีล้วน ให้ซ่อนช่องนี้เมื่อผู้ยกเลิกเป็นฝ่ายขาย |
| **ต้องแจ้งเตือนใครเมื่อดีลถูกยกเลิกหรือไม่** | ยังไม่ได้ตัดสิน ตอนนี้ไม่มีการแจ้งเตือน · **เสนอ: แจ้งผู้จัดการโครงการของงานนั้นและพนักงานขายเจ้าของดีล** เพราะทั้งสองฝ่ายมีงานค้างอยู่กับดีลนั้น ส่วนผู้บริหารดูย้อนหลังได้อยู่แล้วไม่ต้องแจ้ง |
| **ใบแจ้งหนี้ที่ถูกยกเลิกยังพิมพ์ออกได้หรือไม่** | ยังไม่ได้ตัดสิน · **เสนอ: พิมพ์ได้ตามเดิม** พร้อมป้าย "ยกเลิก" บนเอกสาร เพราะใบนั้นเคยส่งถึงลูกค้าไปแล้วจริง |
