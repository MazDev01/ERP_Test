## ระบบ ERP MAZ — โมดูลบัญชี (Accounting Module) · **เอกสารฉบับนี้ไม่ใช่ข้อกำหนดของระบบแล้ว**

> # ⛔ อย่านำเอกสารฉบับนี้ไปพัฒนา
>
> **วันที่ยกเลิก** — 24 ก.ย. 2569 วันเดียวกับที่เขียน
>
> **สิ่งที่เคยตัดสินไว้ในฉบับนี้** — ยูสเคส AC-01 ออกใบลดหนี้ · AC-02 ออกใบเพิ่มหนี้ · AC-03 คืนเงินลูกค้า และกติกาว่าทั้งสามชนิดต้องผ่านการอนุมัติของผู้บริหารก่อนออกเลขที่เอกสาร

>
> **สิ่งที่ระบบทำแทน** — ยูสเคส **SL-09 ยกเลิกดีลหลังปิดการขาย** กลับไปเป็นรูปเดิม คือฝ่ายบัญชียกเลิกดีลหลังรับชำระโดยระบุเหตุผล ใบแจ้งหนี้ที่ยังไม่ชำระถูกยกเลิกตามพร้อมบันทึกผู้ยกเลิกและเวลา ใบเสร็จที่ออกไปแล้วยังอยู่ และ **บริษัทไม่คืนเงินทุกกรณี** · เพิ่มช่องบันทึกเพิ่มเติมของการยกเลิกที่ไม่บังคับกรอก
>
> **ฉบับที่ใช้จริงตอนนี้** — `UseCase_Sales_CancelDeal_SL-09.md`
>
> **รหัส AC-01 ถึง AC-03 ปลดระวางแล้ว** ห้ามนำไปตั้งให้ยูสเคสเรื่องอื่นของโมดูลบัญชี ถ้าเปิดเรื่องนี้ใหม่ให้คืนรหัสเดิมตามความหมายเดิม
>
> **ทำไมยังเก็บไฟล์นี้ไว้** — โค้ดของทั้งสามเรื่องยังอยู่ในโปรเจค (พักไว้ ไม่ได้ลบ ดูหมายเหตุหัวส่วนใน `src/lib/acc-data.ts`) ถ้าฝ่ายบัญชีหรือผู้สอบบัญชีทักท้วง เรื่องนี้เปิดใหม่ได้ และรายละเอียดที่ตัดสินกันไว้อยู่ครบในไฟล์นี้

# เนื้อหาของฉบับที่ถูกยกเลิก (เก็บไว้อ้างอิงเท่านั้น)

> ทุกหัวข้อตั้งแต่บรรทัดนี้ลงไปเป็นข้อความเดิมของฉบับที่ถูกยกเลิก เก็บไว้ตามเดิมโดยไม่แก้ เพื่อให้เปิดเรื่องใหม่ได้ทันทีถ้าต้องกลับมาใช้ · **หัวข้อ "สิ่งที่ยังต้องแก้ในระบบงาน" ไม่มีผลแล้ว ห้ามทำตาม**


## ขอบเขตของเอกสาร

- เอกสารฉบับนี้เพิ่มยูสเคสในโมดูลบัญชีจำนวน 3 รายการ ผู้กระทำหลักคือพนักงานบัญชี ผู้กระทำร่วมคือผู้บริหาร
- เขียนด้วยรูปแบบเดียวกับ `UseCase_PM.docx` และ `UseCase_GM.docx` และเพิ่มแถวเงื่อนไขก่อนเริ่มและเงื่อนไขเมื่อจบตามที่เจ้าของระบบขอ
- ⚠️ ยังไม่มีเอกสารยูสเคสของโมดูลบัญชีในชุดเอกสารเดิม การวางบิลและออกใบเสร็จถูกอ้างถึงในชื่อ SL-05 จากเอกสารโมดูลงานขาย จึงกำหนดรหัสยูสเคสไว้ชั่วคราวว่า **AC-01 ถึง AC-03** และหัวข้อ 3.3.1–3.3.3 รอยืนยันเมื่อเขียนเอกสารโมดูลบัญชีเต็มฉบับ

## กติกาการอนุมัติ — ข้อเดียวใช้กับทั้งสามยูสเคส

> **การแก้เอกสารภาษีที่ออกไปแล้ว หรือการทำให้เงินออกจากบริษัท ต้องผ่านการอนุมัติของผู้บริหาร (CEO) ก่อนเสมอ — ใบลดหนี้ ใบเพิ่มหนี้ และการคืนเงิน เหมือนกันทั้งสามชนิด ไม่มีข้อยกเว้นและไม่มีเพดานยอด**
>
> ระบบออกเลขที่เอกสารให้ **ตอนที่ผู้บริหารกดอนุมัติ** เท่านั้น คำขอที่ยังไม่อนุมัติไม่มีเลขที่ และการตีกลับต้องมีเหตุผลทุกครั้ง (AC-BR-19, AC-BR-23)

เหตุผลของเจ้าของระบบ — ใบลดหนี้ลดรายได้ที่รับรู้ไปแล้ว · ใบเพิ่มหนี้เรียกเก็บลูกค้าเพิ่มหลังเอกสารภาษีออกไปแล้ว กระทบลูกค้าโดยตรง และตามปกติเกิดจากความผิดพลาดของบริษัทเอง · การคืนเงินคือเงินออกจากบัญชีบริษัท ทั้งสามอย่างจึงต้องมีคนสองคนเห็นก่อน หลักการเดียวกับยอดเงินเดือนที่ CEO อนุมัติก่อนฝ่ายบุคคลปิดรอบ

### รอบสอง — คำตัดสินเพิ่มเติม และการปรับให้ตรงกับระบบที่พัฒนาแล้ว

| สาเหตุของใบลดหนี้ห้าอย่าง | **สามอย่าง** — ยกเลิกดีล / ปรับลดยอด–เรียกเก็บเกิน / ออกเอกสารผิด |
| ชื่อสถานะ "ร่าง / รออนุมัติ / อนุมัติแล้ว / ตีกลับ" | **"รอผู้บริหารอนุมัติ" / "ผู้บริหารตีกลับ" / "ออกเอกสารแล้ว"** · **ไม่มีสถานะร่าง** ระเบียนเกิดตอนกดส่งขออนุมัติ |
| "แก้หรือลบร่างที่ยังไม่อนุมัติ" ในตารางสิทธิ์ | ลบไม่ได้ · แก้ได้เฉพาะใบที่ผู้บริหารตีกลับแล้วส่งใหม่ ใบที่รออนุมัติอยู่แตะไม่ได้ทั้งสองฝ่าย |
| AC-01 S-4 "ผู้บริหารอนุมัติได้ทีเดียวทั้งชุด" | ระบบตั้งคำขอแยกใบต่อใบแจ้งหนี้หนึ่งใบจริง แต่ **ผู้บริหารกดอนุมัติทีละใบ** ยังไม่มีการอนุมัติเป็นชุด |
| AC-03 ขั้นตอน 5–7 "อนุมัติแล้วจึงโอน แล้วกลับมาบันทึกวันที่โอนและแนบหลักฐาน" และสถานะ "โอนแล้ว" | ระบบที่ทำแล้วให้ฝ่ายบัญชีกรอกวันที่โอนและหลักฐาน **ตั้งแต่ตอนส่งขออนุมัติ** และไม่มีสถานะ "โอนแล้ว" แยก · **ข้อนี้ยังไม่ลงตัว** ดูประเด็นที่ต้องยืนยันท้ายเอกสาร |

**ไม่มีการเปลี่ยนเลขกฎในรอบนี้** — BR ของทั้งสามยูสเคสยังเป็นเรื่องเดิมทุกข้อ · AC-01 BR-12 เปลี่ยนเนื้อความจาก "ต้องระบุวิธีชดเชย" เป็น "ยังไม่มีการหักกลบในรุ่นนี้" โดยคงเลขเดิม เพื่อไม่ให้เลข BR ในเอกสารอื่นที่อ้างถึงขยับ

| **สิ่งกระตุ้น** | พนักงานบัญชียืนยันการยกเลิกดีลที่มีใบแจ้งหนี้ที่ออกแล้ว หรือเปิดหน้าใบลดหนี้/คืนเงิน (`/acc/credits`) แล้วกดขอออกใบลดหนี้ |
| **ความสัมพันธ์** | ความเกี่ยวเนื่อง : พนักงานบัญชี ผู้บริหาร<br>ต่อยอดจาก : การวางบิลและออกใบเสร็จ (SL-05)<br>การรวม (include) : การยกเลิกดีลหลังปิดการขาย · การอนุมัติของผู้บริหาร (สายเดียวกับการอนุมัติยอดเงินเดือน)<br>ต่อยอดเป็น : ออกใบเพิ่มหนี้ (AC-02) เมื่อใบลดหนี้ออกผิด · คืนเงินลูกค้า (AC-03) เมื่อต้องคืนเงินจริง<br>เกี่ยวข้องกับ : รับงานเข้าใหม่ (PM-01) เมื่อโปรเจคของดีลนั้นถูกยกเลิกตาม |
| **เงื่อนไขก่อนเริ่ม** | 1. ผู้ใช้เข้าสู่ระบบด้วยบทบาทพนักงานบัญชี<br>2. มีใบแจ้งหนี้ที่ออกเลขแล้วอย่างน้อยหนึ่งใบ และยอดที่ยังลดได้ของใบนั้นมากกว่าศูนย์ (ยอดตามใบ − ยอดลดหนี้สุทธิที่ออกแล้ว − ยอดของคำขอที่ยังรออนุมัติ)<br>3. ข้อมูลผู้ซื้อของใบแจ้งหนี้ต้นทางครบตามที่เอกสารภาษีต้องการ<br>4. กรณียกเลิกดีล ดีลอยู่ในสถานะปิดการขายและมีการรับเงินแล้ว ทำให้สิทธิ์ยกเลิกเป็นของฝ่ายบัญชี<br>5. ผู้บริหารมีบัญชีที่ใช้อนุมัติได้ (หน้าคำขออนุมัติของผู้บริหาร `/ceo/approvals`) |
| **ขั้นตอนการทำงานปกติ** | 1. พนักงานบัญชีกดขอออกใบลดหนี้ แล้วเลือกใบแจ้งหนี้ ระบบแสดงลูกค้า ยอดตามใบแจ้งหนี้ ยอดที่รับชำระแล้ว ใบลดหนี้เดิมของใบนั้น และยอดสูงสุดที่ยังลดได้<br>2. พนักงานบัญชีเลือกสาเหตุจากสามอย่าง (ยกเลิกดีล / ปรับลดยอด–เรียกเก็บเกิน / ออกเอกสารผิด) และกรอกเหตุผลเป็นข้อความ ระบบบังคับให้มีเหตุผลทุกครั้ง<br>3. พนักงานบัญชีกรอกยอดที่ต้องการลด ระบบตั้งต้นให้เป็นยอดสูงสุดที่ยังลดได้ แก้เป็นยอดบางส่วนได้ · ระบบถอดยอดที่กรอกเป็นฐานภาษี ภาษีมูลค่าเพิ่ม และภาษีหัก ณ ที่จ่าย ตามสัดส่วนของใบแจ้งหนี้ต้นทาง ไม่คิดภาษีใหม่<br>4. พนักงานบัญชีกดส่งให้ผู้บริหารอนุมัติ ระบบบันทึกคำขอสถานะ "รอผู้บริหารอนุมัติ" **ยังไม่ออกเลขที่เอกสาร** กันยอดนั้นไว้ไม่ให้ใบอื่นใช้ซ้ำ และส่งคำขอขึ้นหน้าคำขออนุมัติของผู้บริหารพร้อมการแจ้งเตือน<br>5. ผู้บริหารเปิดคำขอ เห็นใบแจ้งหนี้ต้นทาง ลูกค้า ยอดที่จะลด แยกบรรทัดภาษี และเหตุผล แล้วกดอนุมัติ<br>6. ระบบออกเลขที่ใบลดหนี้รูปแบบ CN + ปี ค.ศ. สองหลัก + ขีด + เดือนสองหลัก + ลำดับสี่หลัก เช่น CN26-090001 ลงวันที่ออกเป็นวันที่อนุมัติ และบันทึกผู้ตัดสินกับเวลาที่ตัดสิน<br>7. ระบบลดยอดค้างชำระของใบแจ้งหนี้ด้วยยอดก่อนหักภาษี ณ ที่จ่าย (ฐาน + VAT) ชุดเดียวกับที่ยอดค้างใช้อยู่ และผูกใบลดหนี้ไว้กับใบแจ้งหนี้ ดีล ลูกค้า และใบเสร็จถ้ามี<br>8. กรณีสาเหตุคือยกเลิกดีล ดีลถูกบันทึกเป็นยกเลิกไว้ตั้งแต่ตอนกดยกเลิก งวดถัดไปออกใบแจ้งหนี้ไม่ได้ และโปรเจคของดีลเปลี่ยนเป็นยกเลิกตามกติกาเดิม<br>9. ระบบแสดงใบลดหนี้ที่พิมพ์ได้ แสดงป้ายกำกับที่แถวใบแจ้งหนี้พร้อมลิงก์ไปยังใบลดหนี้ และหักยอดออกจากแดชบอร์ดบัญชีตามวันที่ออก |
| **ขั้นตอนการทำงานย่อย** | S-1 : กรณีลดหนี้บางส่วน<br>พนักงานบัญชีกรอกยอดน้อยกว่ายอดสูงสุดที่ลดได้ ระบบออกใบลดหนี้เท่ายอดที่กรอก ใบแจ้งหนี้ยังมียอดค้างส่วนที่เหลือ ยังอยู่ในรายการติดตามหนี้ และยังต้องออกใบเสร็จของส่วนที่เหลือตามปกติ · ใบแจ้งหนี้ใบเดิมออกใบลดหนี้เพิ่มได้อีกจนกว่ายอดสะสมจะครบ<br><br>S-2 : กรณีใบแจ้งหนี้ออกใบเสร็จไปแล้ว<br>ระบบยังออกใบลดหนี้ได้ โดยผูกใบเสร็จของใบแจ้งหนี้นั้นไว้กับใบลดหนี้ให้เอง ใบเสร็จและรายการเงินรับไม่ถูกแก้เพราะเงินเข้าแล้วจริง เงินที่ต้องคืนลูกค้าทำต่อที่ AC-03 ซึ่งเป็นคำขอคนละใบและอนุมัติแยกอีกครั้ง<br><br>S-3 : กรณียกเลิกดีลที่มีใบแจ้งหนี้ค้างหลายใบ<br>ระบบตั้งคำขอใบลดหนี้เต็มยอดที่ยังลดได้ให้ใบแจ้งหนี้ทุกใบที่ยังค้าง หนึ่งคำขอต่อหนึ่งใบแจ้งหนี้ ใช้สาเหตุ "ยกเลิกดีล" และเหตุผลเดียวกับที่บันทึกไว้ในดีล · **ผู้บริหารกดอนุมัติทีละใบ** ยอดค้างของแต่ละใบลดลงตอนใบนั้นได้รับอนุมัติ ไม่ใช่ตอนกดยกเลิกดีล<br><br>S-4 : กรณีดีลยังไม่ได้ออกใบแจ้งหนี้เลย<br>ระบบไม่ตั้งคำขอใบลดหนี้ ยกเลิกดีลได้ตามกติกาเดิม เพราะไม่มีเอกสารที่ต้องกลับรายการ<br><br>S-5 : กรณีออกใบลดหนี้จากหน้าใบลดหนี้โดยไม่ยกเลิกดีล<br>พนักงานบัญชีเลือกสาเหตุว่าปรับลดยอด–เรียกเก็บเกิน หรือออกเอกสารผิด ระบบออกใบลดหนี้ให้ใบนั้นใบเดียว ดีลและโปรเจคไม่เปลี่ยนสถานะ และงวดถัดไปยังออกใบแจ้งหนี้ได้ตามลำดับเดิม<br><br>S-6 : กรณีผู้บริหารตีกลับ<br>ผู้บริหารพิมพ์เหตุผลแล้วกดไม่อนุมัติ ระบบไม่ออกเลขที่เอกสาร คำขอเปลี่ยนเป็นสถานะ "ผู้บริหารตีกลับ" พร้อมเหตุผลบนป้ายสถานะ และคืนยอดที่กันไว้ พนักงานบัญชีแก้ยอดหรือเหตุผลแล้วส่งใหม่ได้ ไม่ต้องสร้างคำขอใหม่ และลำดับเลขที่เอกสารไม่ขาดช่วง |
| **ขั้นตอนกรณีมีข้อยกเว้น** | E-1 : ไม่กรอกเหตุผล — ระบบไม่ให้ส่งขออนุมัติและแจ้งให้กรอกเหตุผลก่อน<br>E-2 : ยอดลดหนี้ทำให้ยอดสะสมเกินยอดตามใบแจ้งหนี้ — ระบบไม่บันทึกและแจ้งยอดสูงสุดที่ลดได้ · ยอดของคำขอที่ยังรออนุมัติถูกนับรวมเป็นยอดที่ใช้ไปแล้วด้วย<br>E-3 : ยอดที่กรอกเป็นศูนย์หรือติดลบ — ระบบไม่บันทึก ใบลดหนี้ต้องมียอดมากกว่าศูนย์<br>E-4 : ข้อมูลผู้ซื้อของใบแจ้งหนี้ต้นทางไม่ครบ — ระบบไม่ให้ส่งขออนุมัติและไม่ให้อนุมัติ พร้อมบอกว่าขาดช่องใด ตรวจทั้งสองฝั่งเพราะคำขอที่ระบบตั้งให้เองตอนยกเลิกดีลไม่ได้ผ่านกล่องกรอกของฝ่ายบัญชี<br>E-5 : ใบแจ้งหนี้ถูกทำเป็นยกเลิกไว้จากข้อมูลเก่าก่อนมีใบลดหนี้ — ออกใบลดหนี้ย้อนหลังให้ครบ โดยใช้วันที่ออกเป็นวันที่อนุมัติจริง ไม่ลงวันที่ย้อนหลัง<br>E-6 : ผู้ใช้ไม่ใช่พนักงานบัญชี — ระบบไม่แสดงปุ่มและปฏิเสธการบันทึกแม้เรียกหน้าจากลิงก์โดยตรง<br>E-7 : ผู้ใช้ไม่ใช่ผู้บริหารแต่กดอนุมัติ — ระบบปฏิเสธ พนักงานบัญชีอนุมัติใบของตัวเองไม่ได้<br>E-8 : ผู้บริหารกดไม่อนุมัติโดยไม่พิมพ์เหตุผล — ระบบไม่บันทึกการตีกลับ<br>E-9 : คำขอถูกตัดสินไปแล้ว (เปิดค้างไว้สองหน้าจอ) — ระบบไม่ตัดสินซ้ำ คำขอที่ไม่ได้อยู่ในสถานะรออนุมัติกดอนุมัติหรือตีกลับไม่ได้ |
| **เงื่อนไขเมื่อจบ** | 1. มีระเบียนใบลดหนี้ที่มีเลขที่ไม่ซ้ำ ผูกกับใบแจ้งหนี้ ดีล ลูกค้า ผู้ขอออก ผู้อนุมัติ และใบเสร็จถ้ามี<br>2. ยอดค้างชำระของใบแจ้งหนี้ลดลงเท่ายอดที่ลด (ก่อนหักภาษี ณ ที่จ่าย) · ลดเต็มยอดแล้วใบนั้นออกจากรายการติดตามหนี้และการแจ้งเตือน · ลดบางส่วนแล้วยังค้างและยังแจ้งเตือนตามยอดที่เหลือ<br>3. แผนงวดชำระคงเดิมทุกงวด ไม่มีงวดใดถูกลบหรือแก้ยอด<br>4. ยอดวางบิลและยอดค้างชำระบนแดชบอร์ดบัญชีลดลงตามยอดใบลดหนี้ตามวันที่ออก ส่วนยอดรับเงินจริงไม่เปลี่ยน<br>5. ใบแจ้งหนี้และใบเสร็จเดิมยังอยู่ครบพร้อมเลขที่เดิม<br>6. คำขอบนหน้าอนุมัติของผู้บริหารปิดแล้ว พร้อมชื่อผู้ตัดสินและเวลาที่ตัดสิน และฝ่ายบัญชีได้รับแจ้งผล<br>7. กรณีต้องคืนเงินลูกค้า ใบลดหนี้ใบนี้พร้อมให้ตั้งคำขอคืนเงินต่อที่ AC-03 |
| **กฎเกณฑ์ทางธุรกิจ** | BR-01 : ยกเลิกดีลที่ออกใบแจ้งหนี้ไปแล้วต้องออกใบลดหนี้เสมอ ห้ามเปลี่ยนใบแจ้งหนี้เป็นยกเลิกโดยไม่มีเอกสารกลับรายการ (AC-BR-10)<br>BR-02 : ใบลดหนี้อ้างใบแจ้งหนี้ได้ใบเดียว ใบแจ้งหนี้หลายใบต้องออกแยกใบ แต่ใบแจ้งหนี้หนึ่งใบมีใบลดหนี้ได้หลายใบ (AC-BR-11)<br>BR-03 : **ลดหนี้บางส่วนได้** ใบลดหนี้ระบุยอดที่ลด อ้างเลขที่เอกสารต้นทาง และระบุเหตุผล · ยอดลดหนี้สุทธิสะสมของใบแจ้งหนี้หนึ่งใบต้องไม่เกินยอดตามใบนั้นเด็ดขาด (AC-BR-12)<br>BR-04 : ใบลดหนี้ที่ออกเลขแล้วยกเลิกไม่ได้ แก้ไม่ได้ และลบไม่ได้ **ออกผิดต้องแก้ด้วยใบเพิ่มหนี้** (AC-BR-13 · ดู AC-02)<br>BR-05 : ใบเสร็จ เงินที่รับแล้ว และภาษีที่ลูกค้าหักไว้ไม่ถูกแก้ด้วยใบลดหนี้ **การคืนเงินเป็นระเบียนแยกต่างหาก** (AC-BR-14, AC-BR-18 · ดู AC-03)<br>BR-06 : พนักงานบัญชีเป็นผู้สร้างและส่งขออนุมัติ ผู้บริหารเป็นผู้อนุมัติ ผู้บริหารและผู้จัดการทั่วไปดูได้อย่างเดียว (AC-BR-16)<br>BR-07 : ใบลดหนี้ไม่ปลดล็อกงวดที่ออกใบแจ้งหนี้ไปแล้ว แผนงวดยังล็อกตามเดิม และดีลที่ยกเลิกแล้วออกงวดถัดไปไม่ได้ (AC-BR-17)<br>BR-08 : ชื่อเอกสารที่พิมพ์ขึ้นกับการจดทะเบียนภาษีมูลค่าเพิ่มของผู้ออก เช่นเดียวกับใบเสร็จ ผู้ใช้เลือกเองไม่ได้<br>BR-09 : **ผู้บริหารต้องอนุมัติก่อนออกใบลดหนี้ทุกใบ ไม่มีเพดานยอด** ตามกติกาข้อเดียวของเอกสารนี้ ตีกลับต้องมีเหตุผล (AC-BR-19)<br>BR-10 : ระบบออกเลขที่เอกสารตอนอนุมัติ ไม่ใช่ตอนส่งขอ คำขอที่ยังไม่อนุมัติไม่มีเลขที่ ไม่กินลำดับเลขที่ และไม่มีสถานะร่าง (AC-BR-23)<br>BR-11 : ยอดของคำขอที่รออนุมัติถูกกันไว้และแก้ไม่ได้ระหว่างรอ ยอดที่ผู้บริหารเห็นจึงเป็นยอดเดียวกับที่บันทึกเสมอ ต้องการแก้ยอดต้องให้ตีกลับก่อน (AC-BR-24)<br>BR-12 : **รุ่นนี้ยังไม่มีการหักกลบยอดที่ลดกับงวดถัดไป** ใบลดหนี้ที่ยังไม่รับชำระหักกับยอดค้างของใบแจ้งหนี้โดยตรง ใบที่รับชำระแล้วไปที่ AC-03 (AC-BR-22 พักไว้ · ดูประเด็นที่ต้องยืนยัน)<br>BR-13 : ออกเอกสารภาษีกลับรายการไม่ได้ถ้าข้อมูลผู้ซื้อยังไม่ครบ ตรวจทั้งตอนขอและตอนอนุมัติ (AC-BR-25) |

| **ผู้กระทำหลัก** | - พนักงานบัญชี (ผู้สร้างและส่งขออนุมัติ)<br>- ผู้บริหาร (ผู้อนุมัติหรือตีกลับ) · **ประเภทยูสเคส** เชิงละเอียด |
| **ผู้มีส่วนเกี่ยวข้องและการใช้ประโยชน์** | พนักงานบัญชี : แก้ใบลดหนี้ที่ออกผิดได้โดยไม่ต้องลบเอกสารที่ส่งออกไปแล้ว<br>ผู้บริหาร : เห็นทุกครั้งที่ต้องกลับรายการของรายการที่เพิ่งอนุมัติไป และทุกครั้งที่บริษัทจะเรียกเก็บลูกค้าเพิ่มจากความผิดพลาดของตัวเอง<br>ลูกค้า : ได้รับเอกสารที่อธิบายว่ายอดที่ลดไปก่อนหน้านี้ถูกปรับกลับเท่าใดและเพราะอะไร โดยอ้างทั้งใบลดหนี้และใบกำกับภาษีต้นทาง |
| **คำอธิบาย** | เมื่อใบลดหนี้ที่ออกไปแล้วมียอดผิด ลดผิดใบ หรือไม่ควรลดตั้งแต่แรก พนักงานบัญชีสร้างคำขอใบเพิ่มหนี้ที่อ้าง **ทั้งใบลดหนี้ใบนั้นและใบกำกับภาษี/ใบแจ้งหนี้ต้นทางเดิม** และระบุเหตุผล ส่งให้ผู้บริหารอนุมัติ อนุมัติแล้วระบบออกเลขที่และเพิ่มยอดหนี้กลับเข้าใบแจ้งหนี้เดิม ใบลดหนี้ใบเดิมยังอยู่ครบพร้อมเลขที่เดิม |
| **สิ่งกระตุ้น** | พนักงานบัญชีเปิดใบลดหนี้ที่ออกเลขแล้วและกดออกใบเพิ่มหนี้ |
| **ความสัมพันธ์** | ความเกี่ยวเนื่อง : พนักงานบัญชี ผู้บริหาร<br>ต่อยอดจาก : ออกใบลดหนี้ (AC-01)<br>การรวม (include) : การอนุมัติของผู้บริหาร (สายเดียวกับ AC-01 และ AC-03) |
| **เงื่อนไขก่อนเริ่ม** | 1. ผู้ใช้เข้าสู่ระบบด้วยบทบาทพนักงานบัญชี<br>2. มีใบลดหนี้ที่อนุมัติและออกเลขแล้ว (สถานะ "ออกเอกสารแล้ว") · ใบที่ยังรออนุมัติหรือถูกตีกลับใช้เป็นต้นทางไม่ได้<br>3. ยอดที่ใบลดหนี้ใบนั้นยังลดอยู่ (ยอดในใบ − ใบเพิ่มหนี้ใบก่อน ๆ) มากกว่าศูนย์<br>4. ข้อมูลผู้ซื้อของใบแจ้งหนี้ต้นทางครบตามที่เอกสารภาษีต้องการ<br>5. ผู้บริหารมีบัญชีที่ใช้อนุมัติได้ |
| **ขั้นตอนการทำงานปกติ** | 1. พนักงานบัญชีเปิดใบลดหนี้แล้วกดออกใบเพิ่มหนี้ ระบบแสดงใบลดหนี้ต้นทาง ใบแจ้งหนี้ต้นทาง ลูกค้า ยอดที่ลดไว้ และยอดสูงสุดที่เพิ่มกลับได้<br>2. พนักงานบัญชีกรอกเหตุผลที่ต้องแก้เป็นข้อความ ระบบบังคับให้มีเหตุผลทุกใบ<br>3. พนักงานบัญชีกรอกยอดที่เพิ่มกลับ ระบบตั้งต้นเท่ายอดที่ใบลดหนี้ยังลดอยู่ แก้เป็นบางส่วนได้ ระบบถอดฐานภาษี ภาษีมูลค่าเพิ่ม และภาษีหัก ณ ที่จ่ายตามสัดส่วนของใบแจ้งหนี้ต้นทาง<br>4. พนักงานบัญชีกดส่งให้ผู้บริหารอนุมัติ ระบบบันทึกคำขอสถานะ "รอผู้บริหารอนุมัติ" **ยังไม่ออกเลขที่เอกสาร** และส่งคำขอขึ้นหน้าคำขออนุมัติของผู้บริหารพร้อมการแจ้งเตือน<br>5. ผู้บริหารเปิดคำขอ เห็นใบลดหนี้ต้นทาง ใบแจ้งหนี้ต้นทาง ยอดที่จะเพิ่มกลับ แยกบรรทัดภาษี และเหตุผล แล้วกดอนุมัติ<br>6. ระบบออกเลขที่ใบเพิ่มหนี้รูปแบบ DN + ปี ค.ศ. สองหลัก + ขีด + เดือนสองหลัก + ลำดับสี่หลัก เช่น DN26-090001 ลงวันที่ออกเป็นวันที่อนุมัติ และบันทึกผู้ตัดสินกับเวลาที่ตัดสิน<br>7. ระบบเพิ่มยอดค้างชำระของใบแจ้งหนี้เดิมกลับเท่ายอดก่อนหักภาษี ณ ที่จ่าย (ฐาน + VAT) แต่ไม่เกินยอดเต็มของใบแจ้งหนี้ และผูกใบเพิ่มหนี้ไว้กับใบลดหนี้และใบแจ้งหนี้<br>8. ระบบแสดงใบเพิ่มหนี้ที่พิมพ์ได้ และแสดงป้ายที่ใบลดหนี้เดิมว่ามีใบเพิ่มหนี้แก้อยู่ พร้อมลิงก์สองทาง<br>9. ระบบบวกยอดวางบิลกลับเข้าแดชบอร์ดบัญชีตามวันที่ออกใบเพิ่มหนี้ |
| **ขั้นตอนการทำงานย่อย** | S-1 : กรณีแก้บางส่วน<br>พนักงานบัญชีกรอกยอดน้อยกว่ายอดที่ใบลดหนี้ลดไว้ ใบลดหนี้ใบนั้นยังลดหนี้อยู่เท่าส่วนที่เหลือ และออกใบเพิ่มหนี้เพิ่มได้อีกจนกว่ายอดสะสมจะครบยอดของใบลดหนี้<br><br>S-2 : กรณีใบลดหนี้นั้นคืนเงินไปแล้ว<br>ใบเพิ่มหนี้ไม่ดึงเงินกลับ ระเบียนการคืนเงินเดิมคงอยู่ ยอดที่ต้องเรียกคืนจากลูกค้ากลายเป็นยอดค้างของใบแจ้งหนี้ ฝ่ายบัญชีต้องตามเก็บตามปกติ · ยอดที่ยังคืนเงินได้ของใบลดหนี้ใบนั้นลดลงตามยอดที่เพิ่มกลับ<br><br>S-3 : กรณีผู้บริหารตีกลับ<br>เหมือน AC-01 S-6 ผู้บริหารพิมพ์เหตุผลแล้วกดไม่อนุมัติ ระบบไม่ออกเลขที่เอกสาร คำขอเปลี่ยนเป็นสถานะ "ผู้บริหารตีกลับ" พร้อมเหตุผล พนักงานบัญชีแก้ยอดหรือเหตุผลแล้วส่งใหม่ได้ ลำดับเลขที่เอกสารไม่ขาดช่วง |
| **ขั้นตอนกรณีมีข้อยกเว้น** | E-1 : ไม่กรอกเหตุผล — ระบบไม่ให้ส่งขออนุมัติ<br>E-2 : ยอดเพิ่มหนี้เกินยอดที่ใบลดหนี้ยังลดอยู่ (หักใบเพิ่มหนี้ใบก่อน ๆ แล้ว) — ระบบไม่บันทึกและแจ้งว่าเกินกว่านี้คือสร้างหนี้ใหม่ ไม่ใช่การแก้ใบลดหนี้<br>E-3 : ยอดที่กรอกเป็นศูนย์หรือติดลบ — ระบบไม่บันทึก<br>E-4 : อ้างใบลดหนี้ที่ยังไม่อนุมัติหรือถูกตีกลับ — ระบบปฏิเสธ คำขอที่ยังไม่ออกเลขให้แก้ที่คำขอโดยตรง ไม่ต้องออกใบเพิ่มหนี้<br>E-5 : ข้อมูลผู้ซื้อของใบแจ้งหนี้ต้นทางไม่ครบ — ระบบไม่ให้ส่งขออนุมัติและไม่ให้อนุมัติ พร้อมบอกว่าขาดช่องใด<br>E-6 : ผู้ใช้ไม่ใช่พนักงานบัญชี — ระบบไม่แสดงปุ่มและปฏิเสธการบันทึก<br>E-7 : ผู้ใช้ไม่ใช่ผู้บริหารแต่กดอนุมัติ — ระบบปฏิเสธ พนักงานบัญชีอนุมัติใบของตัวเองไม่ได้<br>E-8 : ผู้บริหารกดไม่อนุมัติโดยไม่พิมพ์เหตุผล — ระบบไม่บันทึกการตีกลับ<br>E-9 : คำขอถูกตัดสินไปแล้ว — ระบบไม่ตัดสินซ้ำ |
| **เงื่อนไขเมื่อจบ** | 1. มีระเบียนใบเพิ่มหนี้ที่มีเลขที่ไม่ซ้ำ ผูกกับ **ใบลดหนี้ที่แก้และใบแจ้งหนี้ต้นทางเดิมพร้อมกัน** รวมถึงดีล ลูกค้า ผู้ขอออก และผู้อนุมัติ<br>2. ยอดค้างชำระของใบแจ้งหนี้เพิ่มกลับตามยอดใบเพิ่มหนี้ แต่ไม่เกินยอดเต็มของใบ และใบนั้นกลับเข้ารายการติดตามหนี้ถ้ามียอดค้าง<br>3. ใบลดหนี้เดิมยังอยู่ครบพร้อมเลขที่เดิม ไม่ถูกลบและไม่ถูกแก้ · ยอดที่ใบนั้นลดจริงลดลงตามใบเพิ่มหนี้<br>4. ยอดที่ยังคืนเงินได้ของใบลดหนี้ใบนั้นลดลงตามไปด้วย<br>5. แดชบอร์ดบัญชีบวกยอดวางบิลกลับตามวันที่ออกใบเพิ่มหนี้<br>6. คำขอบนหน้าอนุมัติของผู้บริหารปิดแล้ว พร้อมชื่อผู้ตัดสินและเวลาที่ตัดสิน และฝ่ายบัญชีได้รับแจ้งผล |
| **กฎเกณฑ์ทางธุรกิจ** | BR-01 : เอกสารภาษีที่ออกเลขและส่งออกไปแล้วยกเลิกย้อนหลังไม่ได้ ใบลดหนี้ที่ผิดต้องแก้ด้วยใบเพิ่มหนี้เท่านั้น (AC-BR-13)<br>BR-02 : ใบเพิ่มหนี้อ้างใบลดหนี้ได้ใบเดียว **และอ้างใบกำกับภาษี/ใบแจ้งหนี้ต้นทางเดิมด้วยเสมอ** และต้องระบุเหตุผลทุกใบ (AC-BR-13)<br>BR-03 : ยอดเพิ่มหนี้ต้องไม่เกินยอดที่ใบลดหนี้ใบนั้นลดไว้ และต้องไม่ทำให้ยอดลดหนี้สุทธิของใบแจ้งหนี้ติดลบ (AC-BR-12)<br>BR-04 : **ผู้บริหารต้องอนุมัติก่อนออกใบเพิ่มหนี้ทุกใบ ไม่มีเพดานยอด** เพราะเป็นการแก้เอกสารภาษีที่ออกไปแล้วและเรียกเก็บลูกค้าเพิ่ม เลขที่ออกตอนอนุมัติ ตีกลับต้องมีเหตุผล (AC-BR-19, AC-BR-23)<br>BR-05 : ใบเพิ่มหนี้ในระบบนี้ใช้แก้ใบลดหนี้เท่านั้น ไม่ใช้เรียกเก็บงานเพิ่ม งานเพิ่มออกใบแจ้งหนี้งวดใหม่<br>BR-06 : ใบเพิ่มหนี้ไม่ทำให้เงินไหลเข้าเอง ยอดกลับไปเป็นยอดค้างของใบแจ้งหนี้เดิม แล้วรับชำระด้วยใบเสร็จตามปกติ<br>BR-07 : ออกเอกสารภาษีกลับรายการไม่ได้ถ้าข้อมูลผู้ซื้อยังไม่ครบ (AC-BR-25) |

## 3.3.3 Use Case: คืนเงินลูกค้าตามใบลดหนี้ (Refund) *(ยกเลิกแล้ว · บริษัทไม่คืนเงินทุกกรณี)*

| **คำอธิบาย** | ใบลดหนี้ลดภาระภาษีและยอดลูกหนี้ ส่วนการคืนเงินคือเงินที่ออกจากบัญชีบริษัทจริง ทั้งสองไม่ได้เกิดพร้อมกันเสมอ ยูสเคสนี้เริ่มจากใบลดหนี้ที่ออกเลขแล้วของใบแจ้งหนี้ที่รับเงินมาแล้วจริง พนักงานบัญชีระบุยอด วันที่โอนคืน ช่องทาง และหลักฐานการโอน ส่งให้ผู้บริหารอนุมัติ อนุมัติแล้วระบบออกเลขที่ใบสำคัญจ่าย |
| **สิ่งกระตุ้น** | พนักงานบัญชีเปิดใบลดหนี้ที่ออกเลขแล้วและกดคืนเงิน |

| **เงื่อนไขก่อนเริ่ม** | 1. ผู้ใช้เข้าสู่ระบบด้วยบทบาทพนักงานบัญชี<br>2. มีใบลดหนี้ที่อนุมัติและออกเลขแล้ว<br>3. ใบแจ้งหนี้ของใบลดหนี้นั้นมีใบเสร็จแล้ว (รับเงินมาจริง) เงินที่ยังไม่เคยเข้าไม่มีอะไรให้คืน<br>4. ยอดคืนสะสมของใบลดหนี้นั้นยังไม่ครบยอดที่ใบนั้นลดจริง<br>5. ผู้บริหารมีบัญชีที่ใช้อนุมัติได้ |
| **ขั้นตอนการทำงานปกติ** | 1. พนักงานบัญชีเปิดใบลดหนี้แล้วกดคืนเงิน ระบบแสดงยอดที่ใบลดหนี้ลดจริง ยอดที่คืนไปแล้ว และยอดสูงสุดที่คืนได้<br>2. พนักงานบัญชีกรอกยอดที่จะคืน วันที่โอนเงินคืน ช่องทาง (ค่าตั้งต้น "โอนเงินเข้าบัญชีลูกค้า") และหลักฐานการโอน (เลขที่รายการโอนหรือชื่อไฟล์สลิป) · ระบบบังคับให้มีวันที่และหลักฐานครบก่อนส่ง<br>3. พนักงานบัญชีกดส่งให้ผู้บริหารอนุมัติ ระบบบันทึกสถานะ "รอผู้บริหารอนุมัติ" **ยังไม่ออกเลขที่และยังไม่นับเป็นเงินออกในรายงาน** และกันยอดนั้นไม่ให้คืนซ้ำ<br>4. ผู้บริหารเปิดคำขอ เห็นใบลดหนี้ที่รองรับ ใบแจ้งหนี้ต้นทาง ยอดที่จะคืน วันที่โอน ช่องทาง และหลักฐาน แล้วกดอนุมัติ<br>5. ระบบออกเลขที่ใบสำคัญจ่ายรูปแบบ RF + ปี ค.ศ. สองหลัก + ขีด + เดือนสองหลัก + ลำดับสี่หลัก เช่น RF26-090001 และบันทึกผู้ตัดสินกับเวลาที่ตัดสิน<br>6. ระบบนับยอดนี้เป็นเงินออกของแดชบอร์ดตามวันที่โอนคืน แยกบรรทัดจากยอดรับเงินจริง และหักที่ยอดเงินสดสุทธิ<br>7. ใบเสร็จและรายการเงินรับเดิมไม่ถูกแตะ |

| **ขั้นตอนกรณีมีข้อยกเว้น** | E-1 : ไม่มีใบลดหนี้ที่ออกเลขแล้วรองรับ — ระบบไม่ให้สร้างรายการคืนเงิน เงินออกจากบริษัทต้องมีเอกสารรองรับเสมอ<br>E-2 : ใบแจ้งหนี้ของใบลดหนี้นั้นยังไม่มีใบเสร็จ — ระบบปฏิเสธ<br>E-3 : ยอดคืนเกินยอดที่ใบลดหนี้ลดจริงหลังหักรายการคืนเงินอื่น — ระบบไม่บันทึกและแจ้งยอดสูงสุดที่คืนได้<br>E-4 : ไม่กรอกวันที่โอนหรือไม่กรอกหลักฐานการโอน — ระบบไม่ให้ส่งขออนุมัติ<br>E-5 : ยอดที่กรอกเป็นศูนย์หรือติดลบ — ระบบไม่บันทึก<br>E-6 : ผู้ใช้ไม่ใช่พนักงานบัญชี — ระบบไม่แสดงปุ่มและปฏิเสธการบันทึก<br>E-7 : พนักงานบัญชีกดอนุมัติเอง — ระบบปฏิเสธ ผู้อนุมัติต้องเป็นผู้บริหาร<br>E-8 : ผู้บริหารกดไม่อนุมัติโดยไม่พิมพ์เหตุผล — ระบบไม่บันทึกการตีกลับ<br>E-9 : คำขอถูกตัดสินไปแล้ว — ระบบไม่ตัดสินซ้ำ |
| **เงื่อนไขเมื่อจบ** | 1. มีระเบียนการคืนเงินที่มีเลขที่ไม่ซ้ำ ผูกกับใบลดหนี้ ใบแจ้งหนี้ ดีล ลูกค้า ผู้ขอคืนเงิน และผู้อนุมัติ<br>2. ระเบียนมีวันที่โอน ยอดที่โอน ช่องทาง และหลักฐานการโอนครบ<br>3. ใบเสร็จและรายการเงินรับเดิมไม่ถูกแก้ ยอดรับเงินจริงในรายงานไม่เปลี่ยน<br>4. แดชบอร์ดบัญชีแสดงยอดคืนเงินแยกบรรทัดตามวันที่โอน และหักออกจากยอดเงินสดสุทธิ<br>5. ยอดคืนสะสมของใบลดหนี้ไม่เกินยอดที่ใบนั้นลดจริง<br>6. คำขอบนหน้าอนุมัติของผู้บริหารปิดแล้ว พร้อมชื่อผู้ตัดสินและเวลาที่ตัดสิน และฝ่ายบัญชีได้รับแจ้งผล |
| **กฎเกณฑ์ทางธุรกิจ** | BR-01 : การคืนเงินเป็นระเบียนของตัวเอง แยกจากใบลดหนี้ เพราะใบลดหนี้ลดภาระภาษีและลูกหนี้ ส่วนการคืนเงินคือเงินออกจากบัญชี (AC-BR-14)<br>BR-02 : **ผู้บริหารต้องอนุมัติการคืนเงินทุกรายการ ไม่มีเพดานยอด** เพราะเป็นเงินออกจากบัญชีบริษัท ตามกติกาข้อเดียวของเอกสารนี้ (AC-BR-19, AC-BR-20)<br>BR-03 : คืนเงินได้เฉพาะเมื่อมีใบลดหนี้ที่ออกเลขแล้วรองรับ ใบแจ้งหนี้นั้นมีใบเสร็จแล้ว และยอดคืนสะสมไม่เกินยอดที่ใบลดหนี้ลดจริง (AC-BR-21)<br>BR-04 : ส่งขออนุมัติไม่ได้จนกว่าจะมีวันที่โอนและหลักฐานการโอนครบ (AC-BR-20)<br>BR-05 : ใบเสร็จและรายการเงินรับไม่ถูกแก้ด้วยการคืนเงิน รายงานแยกสองบรรทัดเสมอ (AC-BR-18)<br>BR-06 : ระเบียนที่อนุมัติแล้วแก้และลบไม่ได้ คืนผิดต้องบันทึกรับเงินคืนเข้าเป็นรายการใหม่<br>BR-07 : ใบสำคัญจ่ายคืนเงินไม่ใช่เอกสารภาษี แต่มีเลขที่ในชุดของตัวเอง (`RF`) เพื่อใช้อ้างอิงตอนสอบทาน |

## ประเด็นที่ต้องยืนยันกับเจ้าของระบบ

เรื่องลดหนี้บางส่วน ใบเพิ่มหนี้ การคืนเงิน การอนุมัติของผู้บริหารทั้งสามชนิด และจำนวนตาราง (สามตาราง) **ตัดสินแล้ว** ที่เหลือคือประเด็นที่ยังไม่ได้ตัดสินจริง ๆ

| ประเด็น | ข้อเสนอของผู้เขียนเอกสาร |
| --- | --- |
| **ลำดับเวลาของการคืนเงิน — อนุมัติก่อนโอน หรือ โอนแล้วค่อยอนุมัติ** | กติกาเขียนว่าอนุมัติก่อนเงินออก แต่หน้าจอที่ทำแล้วบังคับให้กรอกวันที่โอนและหลักฐานการโอนตั้งแต่ตอนส่งขอ ซึ่งแปลว่าโอนไปก่อนแล้ว · **เสนอ: ยึดอนุมัติก่อนโอน** แยกเป็นสองขั้น — ตอนขอกรอกเพียงยอด ช่องทาง และวันที่ตั้งใจจะโอน อนุมัติแล้วจึงกลับมาบันทึกวันที่โอนจริงกับหลักฐาน แล้วเพิ่มสถานะที่สี่ ("โอนแล้ว") · ถ้าเจ้าของระบบยืนยันว่าทำงานจริงแบบโอนก่อนแล้วให้ผู้บริหารรับรองทีหลัง ต้องแก้ถ้อยคำของกติกาให้ตรง ไม่ใช่ปล่อยให้เอกสารกับระบบพูดคนละอย่าง |
| **การหักกลบยอดที่ลดกับงวดถัดไป** | ระบบยังไม่ทำเลย ใบลดหนี้ที่ยังไม่รับชำระหักกับยอดค้างของใบแจ้งหนี้โดยตรงอยู่แล้ว · **เสนอ: ยังไม่ต้องทำในรุ่นนี้** ถ้าจะทำ ใบแจ้งหนี้ของงวดนั้นต้องมีบรรทัด "หักกลบตามใบลดหนี้ CNxx-xxxxxx" แล้วยอดเรียกเก็บสุทธิลดลง โดยไม่แก้ยอดงวดในแผน |
| **อนุมัติเป็นชุดเมื่อยกเลิกดีลที่มีใบแจ้งหนี้ค้างหลายใบ** | ตอนนี้ผู้บริหารต้องกดอนุมัติทีละใบ · **เสนอ: คงไว้อย่างนี้ก่อน** เพราะแต่ละใบเป็นเอกสารภาษีคนละฉบับและเลขที่คนละใบ ถ้าเจ้าของระบบเห็นว่าช้าเกินไป ค่อยเพิ่มปุ่ม "อนุมัติทั้งชุดของดีลนี้" ที่ออกเลขทีละใบตามลำดับ |
| **สาเหตุของใบเพิ่มหนี้** | ใบลดหนี้เลือกสาเหตุจากสามอย่าง แต่ใบเพิ่มหนี้พิมพ์เหตุผลอิสระอย่างเดียว · **เสนอ: เพิ่มตัวเลือกสามอย่างให้ใบเพิ่มหนี้** (ยอดผิด / ลดหนี้ผิดใบ / ไม่ควรลดตั้งแต่แรก) ให้เข้าคู่กัน และช่วยให้ผู้บริหารตัดสินใจเร็วขึ้น |
| **ช่องทางคืนเงินและบัญชีปลายทาง** | ตอนนี้ช่องทางเป็นข้อความอิสระ และไม่มีช่องบัญชีปลายทางแยก · **เสนอ: ทำช่องทางเป็นดรอปดาวน์ (โอน / เช็ค / เงินสด) + กำหนดเอง** ตามแนวทางเดียวกับค่าตั้งค่าอื่นของระบบ ส่วนบัญชีปลายทางค่อยแยกช่องเมื่อขึ้นฐานข้อมูลจริง |
| ผู้อนุมัติสำรองเมื่อผู้บริหารไม่อยู่ | **เสนอ: ยังไม่ทำ** ให้ผู้บริหารกดอนุมัติจากมือถือได้เหมือนคำขออื่น ถ้าจะให้ผู้จัดการทั่วไปอนุมัติแทนได้ ต้องกำหนดที่หน้าสายอนุมัติเหมือนบทบาทอื่น (ปัจจุบัน `/gm/credits` ดูได้อย่างเดียว) |
| ใบลดหนี้ย้อนหลังของข้อมูลเดิม | ทำแล้วหนึ่งใบ — `CN26-090001` ลดหนี้ `INV26-080031` (ดีล DL-2569-0017) ลงวันที่ที่ทำรายการจริง ไม่ย้อนวันที่ · ถ้ามีใบแจ้งหนี้เก่าที่ถูกตั้งเป็นยกเลิกไว้อีก ต้องไล่ออกให้ครบด้วยวิธีเดียวกัน |
| ถ้อยคำบนหัวเอกสารที่พิมพ์ | ทำตามข้อเสนอเดิมแล้ว ผูกกับการจดทะเบียนภาษีมูลค่าเพิ่มของผู้ออก ผู้ใช้เลือกเองไม่ได้ · **รอยืนยันว่าถ้อยคำถูกต้อง** — "ใบลดหนี้ / ใบกำกับภาษี" และ "ใบเพิ่มหนี้ / ใบกำกับภาษี" |
| รหัสยูสเคสและเลขหัวข้อ | ใช้ AC-01 ถึง AC-03 และหัวข้อ 3.3.1–3.3.3 ไปก่อน รอยืนยันเมื่อเขียนเอกสารยูสเคสโมดูลบัญชีเต็มฉบับ เนื่องจากปัจจุบันการวางบิลถูกอ้างในชื่อ SL-05 ของโมดูลงานขาย |
